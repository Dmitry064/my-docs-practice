**HTTP** (HyperText Transfer Protocol) — протокол прикладного уровня, обеспечивающий передачу гипертекстовых документов и произвольных данных между узлами сети. Изначально создан для Всемирной паутины, но сегодня применяется шире: в REST и GraphQL API, микросервисной архитектуре, IoT, мобильных приложениях.

Ключевое свойство — **отсутствие состояния (stateless)**: сервер не хранит сведений о предыдущих запросах клиента. Каждый запрос самодостаточен, что упрощает масштабирование, но требует передачи аутентификации и контекста в каждом сообщении (например, через заголовки или cookie).

## Модель клиент-сервер

Клиент (браузер, мобильное приложение, скрипт) **инициирует** соединение и отправляет запрос. Сервер **пассивно ожидает** соединения, обрабатывает запрос и возвращает ответ. Такая асимметрия позволяет серверу обслуживать множество клиентов и обновляться независимо от них.

Между клиентом и сервером могут находиться **посредники**:

- **прокси** — принимает запрос от имени клиента (кеширование, фильтрация, анонимизация);
- **шлюз (обратный прокси)** — принимает запрос от имени сервера (балансировка, TLS-терминация);
- **туннель** — слепое ретранслирование данных (например, при апгрейде до WebSocket).

Адресация ресурса выполняется через **URI**, где схема `http` или `https` указывает протокол, а хост и путь — конкретный ресурс.

## Структура HTTP-сообщений

Запрос и ответ имеют схожую структуру из четырёх частей, следующих строго по порядку:

1. **стартовая строка**;
2. **заголовки**;
3. **пустая строка** (разделитель);
4. **тело** (необязательно).

### Стартовая строка запроса

Содержит **метод**, **целевой URI** и **версию**:

```http
GET /reports/2026-05 HTTP/1.1
Host: api.bank.example
```

### Стартовая строка ответа

Содержит **версию**, **код состояния** и **пояснение**. Коды делятся на классы:
- `1xx` — информационные
- `2xx` — успех
- `3xx` — перенаправление
- `4xx` — ошибка клиента
- `5xx` — ошибка сервера. 

Например, `200 OK`, `404 Not Found`, `503 Service Unavailable`.

### Заголовки

Пары «имя: значение», уточняющие запрос или ответ. Бывают:

- **общие** (`Date`, `Cache-Control`);
- **заголовки запроса** (`Host`, `Authorization`, `User-Agent`);
- **заголовки ответа** (`Server`, `Set-Cookie`);
- **сущностные** (`Content-Type`, `Content-Length`).

### Тело сообщения

Необязательная часть, несущая полезную нагрузку: HTML-документ, JSON, файл, данные формы. Отсутствует у большинства GET-запросов и у ответов с кодами `204` и `304`.

## Методы HTTP

Метод определяет **семантику операции** над ресурсом. Ключевые свойства:

- **безопасность** — не изменяет состояние сервера;
- **идемпотентность** — повторный вызов даёт тот же результат.

| Метод  | Назначение                   | Безопасный | Идемпотентный |
| ------ | ---------------------------- | ---------- | ------------- |
| GET    | получить представление       | да         | да            |
| POST   | передать данные на обработку | нет        | нет           |
| PUT    | заменить ресурс целиком      | нет        | да            |
| PATCH  | изменить часть ресурса       | нет        | нет           |
| DELETE | удалить ресурс               | нет        | да            |

### Метод QUERY

В июне 2026 года IETF опубликовал **RFC 10008**, введя метод **QUERY** — безопасный и идемпотентный способ передать **содержимое запроса** (а не только URI) для получения выборки. Он закрывает разрыв между GET и POST: когда параметров слишком много для URL, но менять состояние нельзя.

```http
QUERY /contacts HTTP/1.1
Host: example.org
Content-Type: application/x-www-form-urlencoded

select=surname,givenname,email&limit=10
```

Метод зарегистрирован в реестре HTTP-методов IANA.

## Версии протокола

- **HTTP/1.1** — текстовые сообщения, keep-alive для переиспользования TCP-соединения.
- **HTTP/2** — бинарное фреймирование, мультиплексирование потоков, сжатие заголовков HPACK.
- **HTTP/3** — та же семантика поверх **QUIC** (UDP), снижает задержки и устойчивее к потерям пакетов.
